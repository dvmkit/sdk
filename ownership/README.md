# Caller ownership migration

`caller-migration.json` is a versioned portable allocation of declaring modules, exported symbols, consumer bindings, local static/type/dynamic dependencies and test destinations. It is checked from this repository alone. Entry-point barrels are forwarding declarations, not ownership evidence. The additive phase preserves every existing supported and internal export; new interfaces remain internal.

## Order and bounded units

| Unit | Allocation | Prerequisites |
| --- | --- | --- |
| interfaces | Pure amount conversion and structural wallet credential projection; existing wrappers delegate | This additive patch |
| config-presentation | identity/config-mutation, config-dir caller wrappers, output, next-action, completion-hints, job-store, policy, wallet-probe/funding, caller rail copy, receipt rendering/capture and caller budget parsing | Released additive interfaces; migrate incoming shared dependencies before removing wrappers |
| budget-core (U1b) | Shared ledger schema, spend-entry construction, idempotency/check operations; file-store adapter; caller/service enforcement adapters | Released indefinite spending-history retention; reconcile upstream changes first |
| credit-funding-policy | credit-fund, credit-policy, float policy; shared funding contracts stay SDK | budget-core and released completed-credit-history producer/reader |
| cashu-submit-recovery | wallet-agent spend/recovery-submissions/recovery-melt/recovery/inflight/reserve/release/cash-out/fund orchestration; caller mint migration | credit-funding-policy; shared proof, NUT-13 counter, wallet-store and lock owners unchanged |
| channel-lifecycle | x402 and Tempo config/lifecycle policy, payment orchestration and presentation | Prior caller adapters; channel store/controller and cryptographic operations remain SDK |
| removal | Remove caller implementations only after all runtime/type/dynamic consumers use their allocated adapters | All preceding units and packaged caller/builder/service acceptance |

The config-presentation unit can start with stateless next-action and completion-hints helpers; buildPolicy follows the shared submission-policy declaration cut, and caller callback adapters around the existing SDK writer. It must not copy identity/config-mutation or the output trace singleton while SDK payment consumers still use them; transfer their sole ownership only after every consumer switches. It must defer coupled budget, receipt writers, shared FX-cache ownership, trace emitters and any payment-facing wrapper until the corresponding shared adapter is available. The SDK's defaults module is mixed: caller file names move, shared payment file paths retain the same resolved roots and filenames, builder defaults remain SDK. No state reset or disk-format migration is permitted.

## Implemented interfaces

```ts
interface WalletCredentialConfig {
  x402?: { privateKey: string; network?: string };
  tempo?: { method: string; apiKey?: string; network?: "mainnet" | "moderato" };
}
x402WalletFromConfig(config: WalletCredentialConfig | null): X402Wallet | null;
tempoAccountFromConfig(config: WalletCredentialConfig | null): Promise<TempoCredentialAccount | null>;
```

Caller adapters read their own config and pass only its credential projection. The existing `loadX402Wallet()` and `connectedTempoAccount()` wrappers preserve disk reads and default networks during the additive phase. Key validation and address derivation remain shared. Replacement/disconnect adapters must acquire the existing channel lock before their config lock and use the existing atomic/protected config writer. Do not replace this with a mutable SDK-wide config provider.

`payment-amounts.ts` owns `msatsToUsd`, `usdToMsats`, `msatsToUsdCents`, `msatsToUsdc` and `usdcToMsats`. `currency.ts` forwards the old names. Server consumers import the pure core. Existing integer bounds, decimal-rate interpretation, ceiling and rounding remain unchanged.

## Test allocation and acceptance

Every current test remains in place in this phase. Tests move only with the behavior they protect: config protection/rollback, caller error/output and workflow policy go to caller; checked amount arithmetic, scalar/signature/receipt validation, durable schemas, idempotency, counter monotonicity, process/file locks and server behavior remain SDK. Mixed suites retain distinct cases and split by contract, as recorded in the manifest. Mixed-suite symbol buckets are candidate scope, not a completed case preservation audit: before any suite moves, assign each independently protected case/contract and preserve both shared invariants and caller integration. The acknowledged cross-credit channel association and indefinite ledger retention regressions explicitly stay SDK; caller workflow coverage remains caller. Caller and builder command/package tests stay with their respective repositories.

The guard resolves all literal module specifiers, including configured local aliases, and rejects deliberate static, import-type declaration, inline import-type, quoted dynamic, literal-template dynamic and alias dependencies from the new shared credential core to caller configuration. The existing packed consumer validates all supported entrypoints and the additive internal credential imports in disposable installs. The internal caller bundle must continue excluding server-only modules; after removal, replace its orchestration probes with actual retained shared primitives so this guard still has content.

Required downstream packaged acceptance includes config path/permissions/environment overrides, identity derivation, existing proofs/counters, credits/channels/pending operations, receipt verification, JSON/human output, caller paid submit/recovery, builder drain/repair and generic service runtime imports. Payment-specific live acceptance follows the affected rail. This additive source gate does not establish registry adoption or downstream paid/live acceptance.

## Bounded SDK followups still required

The interfaces unit implements only payment-amounts and wallet-credentials. The cuts below keep existing internal names available while caller consumers move. The receipt-trust and configured-mint-read cuts are implemented; channel exports remain pending.

- **funding-contracts:** relocate `CreditFundRail`, `CreditDrainRail`, `CreditFundingMode`, funding-mode/rail constants and validators, checked funding amount functions and `FundValuation` from credit-fund/credit-policy into shared declaring modules. Keep their existing signatures and internal forwarding names. This is a prerequisite for credit-funding-policy, together with budget-core. `FundCreditArgs`, `CreditFundOutcome`, `CreditFundStatus`, `CreditRailPick`, `CreditRailReason`, `CreditRailSource`, `CreditPlan`, `DrawCeilingSource`, `DrawSkip`, `SuppressedPurchase`, `DeferredFunding` and `FundingSkip` move with caller workflow contracts; current builder/service notice type consumers need caller-contract or structural adapters before removal. Acceptance imports do not establish shared ownership.
- **receipt-trust-contract:** shared `receipt-contracts` now declares `TrustAnchorRead { reachable: boolean; anchor?: ReceiptTrustAnchor }` and its unchanged `ReceiptTrustAnchor` dependency, preserving both former type imports. Upstream completed-credit-history persistence removed the credit-store output import; that conditional diagnostic seam is no longer required. Preserve its archive implementation and tests unchanged. Credit storage imports the shared declaration directly.
- **configured-mint-read:** `loadWalletConfiguredMints(): string[]` is exposed from shared wallet storage for service reads, returning the authoritative wallet's configured mint list without legacy config mutation. Current `loadAgentWallet()?.mints ?? []` already provides the underlying operation; caller `loadConfiguredMints` retains the legacy migration and lock order. This read adapter must replace service use of the migration wrapper before that wrapper moves.
- **channel-primitive-exports:** expose the existing `createTempoChannelStore(context: TempoChannelStoreContext): ChannelStore`, `tempoDescriptorController(descriptor: TempoChannelDescriptor): TempoChannelController | undefined`, `retireTempoChannel(association: TempoChannelAssociation): Promise<void>` and `retireTempoChannelScope(association: TempoChannelAssociation): Promise<void>` through the internal entrypoint if the moved caller session orchestration needs them. Their implementations already live in tempo-channel-store; preserve its AsyncLocalStorage/file lock owner. The x402 storage/lock and shared chain-read/controller operations already have internal names. Split private session/credential operations only after inventorying the moved orchestration's exact bindings; do not duplicate an operation to bypass an export.

Config writer and output trace ownership are deferred, not independently movable code. Caller callback adapters can invoke the current SDK `updateConfig(update: ConfigUpdate): Promise<ConfigUpdateResult>` and shared payment operations. All SDK callers must switch before transferring that writer or output singleton. The same restriction applies to shared FX cache and observability globals.

## Early cuts and consumer adapters

Before removing `policy`, the shared `submission-policy` declares `JobPolicy { maxTotalMsats: number; autoPayBelowMsats: number; maxIncrementMsats: number; maxPayments: number }` as the single shared submission-policy contract. Wallet-agent store and submission-binding retain this persisted/signed recovery schema; caller `buildPolicy` owns argument/config parsing. No schema or binding-byte change is permitted.

Shared `isTestMintUrl` stays SDK because supported server boot, payment-mode and accumulator receipt enforce disposable-mint safeguards. Only mint recommendation policy/copy moves. The supported pricing/currency declarations and their validation/error suite remain wholly SDK.

The x402 network table/lookups and asset resolution stay shared. Wrong-asset advice, network label/list/hint and connect/repin adapters move to caller. `x402VoucherPendingRefusal` moves only after a bounded shared-refusal cut exposes `X402VoucherPendingState { code: "x402_voucher_pending"; creditId: string; fundId: string; channelId: string; endpoint: string; retired: boolean; blockedUntil: number; depositExpiresAt?: number }` through `x402VoucherPendingState(blocking: PendingX402Funding): X402VoucherPendingState`. The authoritative rival-voucher gate rejects with structured code/state; caller formatting consumes those same facts and expiry primitives. Keep batch state, acknowledged association, locks and crypto in SDK. The channel primitive forwards and refusal-facts cut are implemented additively through the existing internal entry. The pure voucher-pending owner supplies the structured rival gate; the existing batch adapter retains caller error output until migration.

Early **builder-notice-rail-adapters** remove unused notice construction APIs and their SDK caller-policy/rail-copy imports while preserving the active deferred-field sink and error drain. Early **service-notice-budget-rail-adapters** clear unreachable notice/budget/rail-copy source imports and migrate acceptance harnesses; the supplied reachability audit does not establish live production service budget-policy execution. Raw imported symbols remain factual source compatibility requirements, not proof of entrypoint reachability. Exact packed runtime/type/dynamic source bindings must clear before SDK declaration/formatter removal. Final qualification after removal cannot satisfy these earlier dependency edges. U1 changes no consumer repository.

## Portable consumer binding schema

Schema version 2 records scalar `consumerBindings` rows with role, sdkEntry, exportedName, declaringModule, declaredSymbol, recognized modes and exact public or opaque sanitized sites. Known literal dynamic destructuring is normalized per symbol; re-exports distinguish value versus type. Generated scaffold imports have generated-runtime/type modes and generator-function site names, including testTemplate separately from builder production source. Canonical rows and grouped compatibility evidence must match. The guard resolves each entry export and checks its actual declaration/name plus runtime value existence; missing/malformed exports, wrong origins and unknown modes fail with distinct controls. The root z namespace declares external:zod with its real SDK forwarding export. No known binding is unresolved.

The pure supported Currency contract is allowed as a new shared-core dependency and has a positive control. Runtime/type/dynamic consumer requirements remain source evidence; bounded early cleanup distinguishes unreachable notice builders from active sinks. Reconcile source snapshots only through explicit checked declaration mappings, such as the unchanged U1 amount extraction from currency to payment-amounts.
